# BaseballGame — 멀티플레이 숫자 야구

언리얼 엔진 C++과 Dedicated Server를 활용한 멀티플레이 숫자 야구 게임입니다. 플레이어는 채팅으로 숫자를 입력하고, 서버가 입력을 검사하여 결과와 승패를 판정합니다.

## 개발 환경

- Unreal Engine: [사용한 버전 입력]
- 개발 언어: C++
- UI: UMG
- 네트워크: Dedicated Server / Client

## 게임 규칙

- 서버는 1 ~ 9 중 중복 없는 숫자 3개로 정답을 생성합니다.
- 각 플레이어에게 최대 3회의 시도 기회가 주어집니다.
- 숫자와 위치가 모두 맞으면 **Strike**, 숫자만 맞으면 **Ball**입니다.
- 일치하는 숫자가 없으면 **OUT**입니다.
- 먼저 3S를 달성한 플레이어가 승리합니다.
- 모든 플레이어가 기회를 소진했는데 정답자가 없으면 무승부입니다.
- 승리 또는 무승부 이후 정답과 시도 횟수가 초기화됩니다.

## 구현한 필수 기능

### 멀티플레이 채팅 및 서버 판정

- 클라이언트의 입력을 Server RPC로 서버에 전달합니다.
- 서버의 GameMode에서 입력 검사와 숫자 야구 판정을 수행합니다.
- 각 PlayerController의 Client RPC를 통해 모든 플레이어에게 결과를 전달합니다.

### 입력 유효성 검사

- 세 자리 입력인지 확인합니다.
- 0이나 숫자가 아닌 문자가 포함되었는지 검사합니다.
- 중복된 숫자가 포함되었는지 검사합니다.
- 잘못된 입력에는 재입력을 안내하며 시도 기회를 차감하지 않습니다.

### 플레이어별 시도 횟수 관리

- PlayerState에서 각 플레이어의 현재·최대 시도 횟수를 관리합니다.
- 유효한 추측에만 해당 플레이어의 현재 시도 횟수를 증가시킵니다.
- 채팅 결과에 `Player1(1/3)` 형태로 횟수를 표시합니다.
- 3회를 모두 사용한 플레이어의 추가 시도을 차단합니다.

### 승리·무승부 및 게임 리셋

- 3S를 달성한 플레이어의 승리를 알립니다.
- 모든 플레이어가 기회를 소진하면 무승부를 알립니다.
- 결과 공지 후 새 정답을 생성하고 모든 플레이어의 횟수를 초기화합니다.
- 결과 안내는 다음 라운드의 첫 유효한 추측이 들어오면 지워집니다.

### C++ 공통 함수 라이브러리

`BassballGameFunctionLibrary`에 네트워크 디버깅용 함수를 구현했습니다.

- `MyPrintString()`: 실행 환경에 따른 화면·로그 출력
- `GetNetModeString()`: 네트워크 실행 모드 확인
- `GetRoleString()`: 액터의 LocalRole·RemoteRole 확인

## 주요 클래스 역할

| 클래스                           | 역할                                      |
| ----------------------------- | --------------------------------------- |
| `ABGGameModeBase`             | 정답 생성, 입력 검사, 판정, 시도 횟수 증가, 승패 판단과 리셋   |
| `ABGPlayerController`         | 입력 전달, Server/Client RPC, 위젯 생성과 메시지 출력 |
| `ABGPlayerState`              | 플레이어 이름과 개인별 시도 횟수 관리·복제                |
| `ABGGameStateBase`            | 접속 안내 브로드캐스트                            |
| `BassballGameFunctionLibrary` | 공통 출력 및 네트워크 디버깅 함수                     |
| `WBP_NotificationText`        | 접속·게임 결과 안내 표시                          |
| `UBGChatInput`                | 채팅 입력 이벤트 연결·해제, Enter 입력 시 PlayerController에 내용 전달 및 입력창 초기화 |


## 구현 중 해결한 문제

### 시도 횟수가 이전 값으로 표시되는 문제

처음에는 클라이언트에서 이름과 시도 횟수를 문자열로 만든 뒤 서버로 전달했습니다. 서버에서 횟수를 증가시켜도 이미 만들어진 문자열은 바뀌지 않아 이전 횟수가 표시되었습니다.

클라이언트에서는 원본 입력만 전달하고, 서버에서 횟수를 증가시킨 다음 출력 문자열을 생성하도록 변경했습니다.

### 게임 리셋 후 이전 결과 안내가 남는 문제

결과를 확인할 수 있도록 리셋 시 안내를 유지하고, 다음 유효한 추측을 처리할 때 모든 플레이어의 안내 문구를 비우도록 수정했습니다.

### 리셋이 반복 호출되는 문제

공지 반복문 안에 있던 `ResetGame()`을 반복문 밖으로 이동하여, 승리 또는 무승부마다 한 번만 호출하도록 수정했습니다.

## 구현 범위 및 제한 사항

- 필수 기능을 중심으로 구현했습니다.
- 도전 기능인 턴 제어, 제한 시간, 시간 초과 시 기회 차감은 구현하지 않았습니다.
- 현재 숫자 야구 입력 규칙에 맞지 않는 메시지는 일반 채팅으로도 전달되며, 입력한 플레이어에게 숫자 입력 안내가 함께 표시됩니다.

## 학습 내용

VOD 내용을 토대로 코드 구현 및 내용 정리를 하며 서버에서 규칙과 판정을 관리하고, 클라이언트가 입력을 전달해 결과를 표시하는 흐름을 학습했습니다. 
또한 PlayerState를 이용한 개인별 데이터 관리와 RPC를 통한 메시지 전달을 구현했습니다.
